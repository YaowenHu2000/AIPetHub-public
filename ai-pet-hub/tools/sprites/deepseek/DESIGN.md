### 怎么做的（脚本都在这个目录）

- `gen_set.py bases`：所有底图 / 单张 / 走路整图一次并发发出去（32 个请求，并行 8）。输入只有 `master.png`。
- `post_set.py pick`：底图下半身对齐到母版。`gen_set.py sheetsA`：各循环前半段的 3×2 整图（16 个请求）。
- `gen_set.py sheetsB`：后半段。**压接缝的做法**：image 1 = 底图，image 2 = 已挑好的前半段整图，要求线条、卷发、大小、格内位置都照 image 2 画。
- `post_set.py slice`：切格 → 整格平移到底图脚底 → `fit_keys.py` → `normcolor.py` → `pin_head.py` → 被画布切到的边 3% 渐隐（没被切的不动）。
  `height`：整套按同一比例缩放让身高和底图一致；`walk`：走路按头部对到母版；`single` / `blink`：单张和眨眼。最后统一清一遍 alpha ≤ 24 的底雾。
- `check_pos.py`：量各帧头、脚相对 idle 的位置（状态切换跳不跳）。`preview.py`：预览图和相邻帧差。
- 说明：`check_pos.py` 和 `post_set.py` 里的 `place` 子命令不是我写的，是中途另一个进程留在这个目录里的；我看过内容、用了它们（走路整体下移 4 像素用的 `place`）。

- 每套都在深色底、浅色底上逐帧看过；109 张都是 640×640 RGBA，没有贴到画布边、没有被切。头顶有特效的（思考的水泡、睡觉的泡）离上边 ≥ 10 像素。

- 思考的「!」离上边太近的问题：没有把人缩小（缩了切换状态时会小一圈），而是重画了后半段，特效往旁边走，现在最高点离上边 10–16 像素。

### 没做好 / 要知道的

- **没在真实窗口里看过**：只看了静态的预览图和数字，没有连起来播。接进 App 后要实际看一遍循环的观感，尤其是两段接缝和 dragged。
- **dragged 可能太闹**：App 里 12 帧来回播、100 ms 一帧，这套是每帧左右交替，等于 10 Hz 扑腾。嫌快的话照吉佩缇的做法在 `STRUGGLE_PICK` 里只挑几帧、放慢。
- **走路只有 6 张不同的图**排成 8 帧，头比 idle 略大；是正面原地踏步，不是侧面走。
- **fast 查阅**那张整图带一层很淡的光晕（alpha ≤ 24 的像素约 3.6%），成品里已清零。
- **fast 形态的头发飘到右边**，最远到 x≈633（640 里），没被切但很靠边。
- **书和键盘上的小字**每帧不完全一样（模型每格都重画），小尺寸下看不出，放大能看到。
- **手**：各套在 320 的预览格里看过，没发现多指；没有每一帧都放大到原尺寸逐只手查。
- 线条比现有三位的 1024 原图略软（每格 512 放大到 640）。
- 设定图的作者和授权仍未查证（见最上面），公开发布前要确认。

## 接入说明

**骨骼**：不用配任何东西就会走逐帧。

- 判断在 `web/js/stage/pet.js`：`usesRig(state) { return !!this.rig && !RIG_OFF_STATES.has(state); }`。
  `this.rig` 只有 `attachRig()` 里 `window.PetRig.create(id, body)` 返回了控制器才会有；
  `web/rig/src/pet-rig.js` 的说明是「没有这位的模型数据（`window.__PET_RIGS[id]`）就返回 null，App 继续用逐帧」。
- 所以**没有单独的配置项**：有没有骨骼取决于有没有 `web/rig/<id>/rig.js` 并被页面加载。deepseek 不建 `web/rig/deepseek/` 就是全逐帧。
  （这是读代码得出的结论，没有实际跑起来验证 `create` 对新 id 确实返回 null。）
- 没有骨骼时，待机用 `idle.png` + 定时眨眼（`idle_blink_half → closed → half`），拖拽用 `dragged_g00…g11`。

**要改的地方**（我都没动）：
